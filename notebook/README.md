# Capstone Notebook – Diabetic Readmission

This folder contains a single, end‑to‑end Jupyter notebook: **`capstonefinal.ipynb`**.  
The notebook documents the full workflow for the UMBC DATA 606 capstone project on predicting 30‑day hospital readmission risk in diabetic patients using the UCI “Diabetes 130‑US hospitals for years 1999–2008” dataset.[web:100][file:99][file:98]

---

## Notebook Overview

**`capstonefinal.ipynb`** combines all stages of the project:

1. **Data loading and understanding**  
   - Imports the main dataset (`diabetic_data.csv`) and ID mapping file (`IDS_mapping.csv`).[file:99][file:98]  
   - Describes key variables: demographics, utilization, diagnoses, diabetes medications, lab values, and the `readmitted` target.[web:100]

2. **Exploratory Data Analysis (EDA)**  
   - Summarizes patient population, admission patterns, and readmission rates.  
   - Examines class imbalance, missing values (`?`, `None`, `NULL`), and distributions of high‑impact features (e.g., age, prior visits, A1C, insulin use).[web:100][file:99]

3. **Preprocessing & Feature Engineering**  
   - Cleans and encodes categorical variables, using `IDS_mapping.csv` to map ID fields such as `admission_type_id`, `discharge_disposition_id`, and `admission_source_id` to human‑readable labels.[file:98]  
   - Creates derived features used later in the app, such as:
     - Age groups and utilization flags (e.g., high prior inpatient/emergency use).  
     - Grouped admission types and discharge dispositions.  
     - Medication burden (`num_medications`, many‑meds indicator) and diabetes control indicators (A1C categories, insulin change patterns).[file:99][web:100]

4. **Model Development**  
   - Builds a scikit‑learn pipeline that includes preprocessing and a **stacking ensemble** classifier.  
   - Trains baseline models and the stacked model; compares performance using F1, precision/recall, ROC‑AUC, and confusion matrices to select the final model.[web:104][web:113]

5. **Threshold Optimization & Export**  
   - Searches for the probability threshold that maximizes F1 score on a validation set.  
   - Saves artifacts for deployment:
     - `stacking_model_pipeline.pkl` – trained pipeline model.  
     - `model_threshold.npy` – best F1 decision threshold.  

6. **App Integration (optional section)**  
   - Demonstrates how the saved model and threshold are used in the Streamlit app for single‑patient and batch CSV prediction.

---

## How to Run the Notebook

 1. **Start Jupyter Notebook**
 2. **Open and run**

- Open `capstonefinal.ipynb`.  
- Run all cells from top to bottom to:
  - Reproduce EDA figures and tables.  
  - Train the final stacking model.  
  - Regenerate `stacking_model_pipeline.pkl` and `model_threshold.npy` used by the Streamlit application.

---

## Relation to Data and App

- **Data** – expects `diabetic_data.csv` and `IDS_mapping.csv` in the data repo/folder as described in the data README.md
- **App** – the Streamlit app (`app.py`) loads the model and threshold generated by `capstonefinal.ipynb` to provide interactive 30‑day readmission risk predictions for single patients and batch CSV uploads.

This single notebook is the primary, self‑contained record of the analysis and modeling for the capstone project.
